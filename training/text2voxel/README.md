# Training Text2Voxel-64

The code that trains the in-browser text-to-3D model. It runs as two Kaggle
kernels: **K1** prepares the data on a CPU machine and **K2** trains and exports the
model on Kaggle's two-T4 GPU machine. Nothing here needs a local GPU and nothing is
trained locally; the only local run is the optional smoke check at the end.

What the model is, what it was trained on, how it is evaluated and its licence
(**non-commercial research use only**) are in the
[model card](../../docs/MODEL_CARD.md). This file is the operating manual.

## Files

| File | Role |
| --- | --- |
| `common.py` | Shared by both kernels, and the contract with the runtimes: the pinned MiniLM revision and `TextEncoder` (tokenise, mean-pool, L2-normalise), the ModelNet class names, colour palette and caption templates, and small I/O helpers |
| `k1_prep.py` | K1: download and voxelise the data, embed every caption |
| `k2_train.py` | K2: train the shape VAE and the diffusion prior, evaluate, export ONNX + `meta.json` |
| `build_kernels.py` | Inlines `common.py` into each stage (Kaggle script kernels are single files) and writes `kaggle/<k1\|k2>/kernel.py` + `kernel-metadata.json` |
| `kaggle/k1/`, `kaggle/k2/` | Generated by `build_kernels.py` and gitignored. Edit the sources, never these, and rebuild before every push |

## The two kernels

| | K1 - data prep | K2 - train and export |
| --- | --- | --- |
| Kernel | `arunkumarpucha/text2voxel-k1-prep` | `arunkumarpucha/text2voxel-k2-train` |
| Machine | CPU | GPU, `NvidiaTeslaT4` (Kaggle's "GPU T4 x2") |
| Internet | on: Text2Shape from `text2shape.stanford.edu` (a 1.9 GB voxel zip + 11 MB of captions), MiniLM from Hugging Face, `pip install onnxruntime tokenizers` | on: MiniLM from Hugging Face, `pip install onnxruntime onnx tokenizers` |
| Inputs | Kaggle dataset `balraj98/modelnet40-princeton-3d-object-dataset` | K1's output (attached as a kernel source) |
| Time | about 28 minutes to the embedding step on the first run (Text2Shape ~12 min, ModelNet ~12 min); the full run (with embeddings) took 2,117 s (35 min) | VAE 110 min + prior 20 min of training, plus latent encoding, evaluation and export. Expect roughly 2.5 hours in total (v1: 8,205 s = 2 h 17 min, `k2_report.json` → `seconds`) |

Both budgets are fixed wall-clock times, so K2 finishes on schedule whatever the GPU
speed. Each stage times its first steps and fits its cosine learning-rate schedule
to the number of steps that will fit.

### K1 outputs (`/kaggle/working`)

| File | Contents |
| --- | --- |
| `t2s_occ.npy` | uint8 `[N, 32768]`: 64³ Text2Shape occupancy, bit-packed |
| `t2s_col32.npy` | uint8 `[N, 32, 32, 32, 3]`: mean colour of the occupied children of each 32³ cell |
| `t2s_models.json`, `t2s_captions.json` | ShapeNet model id + category per row; `{shape, text}` caption pairs |
| `mn_occ.npy`, `mn_meta.json` | 64³ ModelNet40 occupancy, bit-packed; class / split / file / fill ratio per row |
| `text_strings.json`, `text_emb.npy` | every caption and template string, and its MiniLM embedding (float16 `[S, 384]`) |
| `montage_t2s.png`, `montage_modelnet.png` | axis projections for choosing the orientation (below) |
| `k1_report.json` | counts, NRRD header, voxelisation failures and fill ratios, an embedding sanity probe |

The arrays total roughly 2.4 GB (occupancy 0.9 GB, Text2Shape colour 1.5 GB). Do not
download them; K2 reads them on Kaggle.

### K2 outputs (`/kaggle/working`)

| File | Contents |
| --- | --- |
| `model/decoder.onnx`, `model/prior.onnx`, `model/meta.json` | **The release.** Formats are specified in the [model card](../../docs/MODEL_CARD.md#files) |
| `samples_final.png` | 16 fixed prompts, front / side / top views of each sample: the qualitative check |
| `k2_report.json` | orientation used, GPU count, step counts, the last VAE validation points, final prior loss, full evaluation including ModelNet per-class accuracy, total seconds |
| `vae.pt`, `prior.pt` | PyTorch checkpoints (VAE; EMA prior + latent mean/std) for resuming or analysis |

## Prerequisites

- A Kaggle account with phone verification (Kaggle requires it for GPU and internet
  access in kernels).
- The Kaggle CLI: `pip install kaggle`, with an API token in `~/.kaggle/kaggle.json`
  (or `KAGGLE_USERNAME` / `KAGGLE_KEY` in the environment).
- If you are not the maintainer, set `OWNER` in `build_kernels.py` to your Kaggle
  username. It sets both kernel ids and K2's kernel source.
- For publishing: the GitHub CLI (`gh`), authenticated with write access to the
  repository.

## Running a training

All commands run from the repository root.

**1. Build the kernels.**

```bash
python training/text2voxel/build_kernels.py
```

It prints the two directories it wrote and compiles each generated `kernel.py` to
catch syntax errors before anything is pushed.

**2. Push K1 and wait for it.**

```bash
python -m kaggle kernels push -p training/text2voxel/kaggle/k1
python -m kaggle kernels status arunkumarpucha/text2voxel-k1-prep
```

**3. Check K1 and choose the orientation.** Look at the montages and
`k1_report.json` on the kernel's Output tab, or fetch just those files:

```bash
python -m kaggle kernels output arunkumarpucha/text2voxel-k1-prep -p k1-check \
    --file-pattern "(k1_report\.json|montage_.*\.png)$"
```

Each montage row is one shape; column *k* is the view looking along raw axis *k*,
with image rows = the next raw axis (top to bottom) and columns = the last. Work out
which raw axis is "up" and which is the object's front for each source, then set
`ORIENT` near the top of `k2_train.py`:

```python
ORIENT = {  # values used for text2voxel-v1
    "t2s": {"perm": (2, 0, 1), "flip": (0, 2)},  # perm: raw axis that becomes canonical x, y, z
    "mn": {"perm": (0, 2, 1), "flip": (2,)},     # flip: canonical axes to reverse afterwards
}
```

The canonical frame is glTF: x right, y up, z towards the viewer. Also check in
`k1_report.json` that the shape and caption counts are plausible,
`mn_failure_count` is small, and in `embedding_probe` the paraphrase pair scores
higher than the unrelated pair.

**4. Rebuild and push K2.**

```bash
python training/text2voxel/build_kernels.py
python -m kaggle kernels push -p training/text2voxel/kaggle/k2
python -m kaggle kernels status arunkumarpucha/text2voxel-k2-train
```

In the log, `VAE: … ms/step -> ~N steps` and `prior: … ms/step -> ~N steps` give
the step counts the schedules were fitted to. VAE validation prints every 1000 steps.
That periodic check uses the first 512 held-out shapes, which are all Text2Shape
rows, so its `val_iou_modelnet` is `null`; the final evaluation covers every
held-out shape. The run ends with `K2 COMPLETE`. If ONNX export parity exceeds 1e-3
the kernel fails instead of publishing a bad file.

**5. Download only what ships** (about 33 MB, not the checkpoints):

```bash
python -m kaggle kernels output arunkumarpucha/text2voxel-k2-train -p t2v-out \
    --file-pattern "(decoder\.onnx|prior\.onnx|meta\.json|k2_report\.json|samples_final\.png)$"
```

**6. Check the run before publishing.**

- `samples_final.png`: chairs and tables should follow their prompts; ModelNet
  prompts should give the right category, the right way up, facing the right way.
- `meta.json` must **not** contain `"smoke": true`, and `metrics`, `training` and
  `parity` should hold real numbers.
- `k2_report.json` → `prior_eval`: the held-out caption IoU should clearly beat the
  shuffled-caption IoU, and `modelnet_per_class` shows which categories failed.

## Publishing the `text2voxel-v1` release

The web build, the Pages workflow and the backend installer all download the model
from this release. MiniLM is not in it: it comes from Hugging Face at the pinned
revision.

**1. Create the release** (published, not a draft: drafts cannot be downloaded
anonymously):

```bash
gh release create text2voxel-v1 t2v-out/model/decoder.onnx t2v-out/model/prior.onnx t2v-out/model/meta.json \
    --repo PuchaArunKumar/AI-driven-3D-blueprint-generator \
    --title "Text2Voxel-64 v1" \
    --notes "Text2Voxel-64 model files. Non-commercial research use only: trained on Text2Shape (ShapeNet) and ModelNet40. See docs/MODEL_CARD.md."
```

The paths depend on where step 5 put the files; adjust them if the `model/`
directory was flattened. To replace files in an existing release, use
`gh release upload text2voxel-v1 <files> --clobber` and then update the checksums.

**2. Record the checksums** in `models/manifest.json`, which lists every model file
with its download URL and `sha256`. The MiniLM entries are already filled in; the
three `text2voxel/*` entries stay `null` until you paste the values below. The
fetchers verify a file whenever its `sha256` is set, and a checksum is what lets
them replace a stale local copy without `--force`.

```bash
sha256sum t2v-out/model/decoder.onnx t2v-out/model/prior.onnx t2v-out/model/meta.json
# PowerShell: Get-FileHash -Algorithm SHA256 t2v-out\model\*
```

**3. Fill in the model card.** Replace every `TBD` in
[`docs/MODEL_CARD.md`](../../docs/MODEL_CARD.md) (and the timing TBDs in this file)
from `meta.json` and `k2_report.json`.

**4. Replace the local placeholder and check parity with the real model.**

```bash
node frontend/scripts/fetch-models.mjs --force         # frontend/public/models/
python backend/scripts/install_text2voxel.py --force   # backend/models/text2voxel/
node frontend/scripts/verify-text2voxel.mjs            # browser runtime vs meta.json reference
cd backend && pytest tests/test_text2voxel.py          # backend runtime vs meta.json reference
```

**5. Push to `main`.** The GitHub Pages workflow downloads the release files, so the
next deployment serves the trained model.

A retrained model that changes the file contract should get a new tag
(`text2voxel-v2`), a bumped `version` in `meta.json` and an updated `release` in
`models/manifest.json`, rather than overwriting `text2voxel-v1` under deployed sites.

## Local smoke run

`T2V_SMOKE=1` shrinks K2 to a shape check that takes about a minute: 0.3 min of VAE
training, 0.2 min of prior training, tiny batches and at most 64 shapes per source. It still runs evaluation, the montage and the full ONNX export with parity
checks. This is how the development placeholder (`"smoke": true`) was made.

```bash
T2V_SMOKE=1 T2V_INPUT=<dir with K1-format files> T2V_OUT=<output dir> T2V_MINILM=<minilm dir> \
    python training/text2voxel/kaggle/k2/kernel.py
```

- `T2V_INPUT` (default `/kaggle/input`) is searched recursively for K1's file names.
  The real K1 arrays are ~2.4 GB, so for a local check use a handful of synthetic
  shapes in the same format; no generator for those is included in the repository.
- Always set `T2V_OUT`: `k2_train.py` creates `<T2V_OUT>/model` as soon as it is
  imported, and its default `/kaggle/working` would otherwise be created at the root
  of the current drive.
- `T2V_MINILM` (default `/tmp/minilm`) is where the pinned MiniLM files are fetched.
- It needs torch, numpy, matplotlib, onnx, onnxruntime and tokenizers, and
  pip-installs the last three into the current environment if they are missing.

## Changing the training code

- **`common.py` is shared with the runtimes.** The MiniLM pin, `MAX_TOKENS` and the
  pooling are reproduced by `frontend/src/lib/text2voxel/` and
  `backend/app/providers/threed/text2voxel.py`; change them there too, and re-run
  K1, which stores the embeddings. Changing caption templates or the palette needs
  no K1 re-run: K2 embeds any template string K1 did not.
- **The sampler and schedule** (`ddim_sample`, `cosine_alphas_cumprod`) are mirrored
  in both runtimes. `meta.json` carries the full `alphas_cumprod` table and a
  reference sample; the runtimes' parity checks fail if they drift.
- **The export contract** (input and output names and shapes of `decoder.onnx` and
  `prior.onnx`, the voxel frame and index order) is fixed; see the
  [model card](../../docs/MODEL_CARD.md#files).
- Rebuild the kernels after any edit. `kaggle/*/kernel.py` is only a copy.
